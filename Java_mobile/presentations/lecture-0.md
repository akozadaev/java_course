## 1. Зачем нужна мобильная разработка

Мобильное приложение - это программный продукт, рассчитанный на работу в условиях ограниченных ресурсов, сенсорного ввода, переменного качества сети и постоянного взаимодействия с системными сервисами устройства: камерой, геолокацией, уведомлениями, файловым хранилищем, контактами, датчиками.

Главные особенности мобильной разработки:

---

## 1. Зачем нужна мобильная разработка · продолжение

- приложение должно быстро запускаться и не блокировать интерфейс;
- пользователь может в любой момент свернуть приложение, повернуть экран, потерять сеть или закрыть процесс;
- интерфейс должен адаптироваться к разным размерам экрана;
- важна экономия памяти, батареи и сетевого трафика;
- приложение работает внутри модели разрешений и ограничений операционной системы.

Примеры мобильных приложений:

---

## 1. Зачем нужна мобильная разработка · продолжение

- банковское приложение: высокая безопасность, работа с сетью, биометрия;
- навигатор: геолокация, карты, фоновая работа;
- мессенджер: сеть, локальная база, push-уведомления;
- учебное приложение: списки, прогресс, офлайн-доступ;
- интернет-магазин: каталог, корзина, платежи, REST API.

---

## 2. Классификация мобильных приложений

### Нативные приложения

Нативное приложение создается под конкретную платформу с использованием ее официальных инструментов.

Для Android это Java или Kotlin, Android SDK, Android Studio. Для iOS - Swift или Objective-C, iOS SDK, Xcode.

Преимущества:

---

## 2. Классификация мобильных приложений · продолжение

- максимальный доступ к возможностям устройства;
- высокая производительность;
- хороший пользовательский опыт;
- полная интеграция с платформой.

Недостатки:

- для Android и iOS обычно нужны отдельные команды или отдельные кодовые базы;
- выше стоимость поддержки;
- необходимо учитывать различия платформ.

### Гибридные приложения

---

## 2. Классификация мобильных приложений · продолжение

Гибридное приложение использует веб-технологии: HTML, CSS, JavaScript. Оно запускается внутри специального контейнера WebView.

Преимущества:

- можно переиспользовать веб-разработку;
- быстрее сделать простой прототип;
- одна значительная часть кода может работать на разных платформах.

Недостатки:

---

## 2. Классификация мобильных приложений · продолжение

- производительность и отзывчивость ниже, чем у нативных приложений;
- сложнее добиться платформенного поведения;
- доступ к системным функциям часто требует плагинов.

### Кроссплатформенные приложения

Кроссплатформенные приложения создаются на фреймворках вроде Flutter, React Native, .NET MAUI. Разработчик пишет одну кодовую базу, а фреймворк помогает запускать ее на Android и iOS.

Преимущества:

---

## 2. Классификация мобильных приложений · продолжение

- одна команда может разрабатывать приложение для нескольких платформ;
- высокая скорость разработки;
- единая бизнес-логика.

Недостатки:

- зависимость от фреймворка;
- не все платформенные возможности доступны сразу;
- сложные интерфейсы и интеграции иногда требуют нативного кода.

---

## 3. Обзор платформ

Android - открытая мобильная платформа от Google, основанная на Linux. Она используется на смартфонах, планшетах, телевизорах, автомобилях, часах и других устройствах.

iOS - закрытая платформа Apple. Отличается высокой унификацией устройств, строгими требованиями к публикации приложений и сильной интеграцией внутри экосистемы Apple.

HarmonyOS - платформа Huawei для разных типов устройств. В некоторых регионах и сценариях она важна как альтернатива Android.

В учебном курсе используется Android, потому что:

---

## 3. Обзор платформ · продолжение

- Android Studio доступна бесплатно;
- Java поддерживается официально;
- можно запускать приложения на эмуляторе без физического устройства;
- Android хорошо подходит для изучения жизненного цикла, UI, локального хранения и REST-клиентов.

---

## 4. Архитектура Android

Android можно представить как многоуровневую систему.

### Linux Kernel

Нижний уровень Android основан на ядре Linux. Он отвечает за:

- управление процессами;
- работу с памятью;
- драйверы устройств;
- безопасность;
- сетевой стек;
- энергопотребление.

---

## 4. Архитектура Android · продолжение

Разработчик приложений редко взаимодействует с ядром напрямую, но все приложение работает поверх этого уровня.

### Hardware Abstraction Layer

HAL изолирует Android Framework от конкретного оборудования. Например, разные производители камер могут иметь разные драйверы, но Android предоставляет единый интерфейс для работы с камерой.

### Android Runtime

---

## 4. Архитектура Android · продолжение

Android Runtime, или ART, выполняет байткод приложения. Java-код компилируется не в обычный JVM-байткод для настольной Java, а в формат, подходящий для Android. ART отвечает за выполнение, сборку мусора и оптимизацию.

Исторически в Android использовался Dalvik, но современные версии используют ART.

### Native Libraries

На этом уровне находятся системные библиотеки: работа с графикой, SQLite, SSL, мультимедиа, WebView и другие компоненты.

### Application Framework

---

## 4. Архитектура Android · продолжение

Это набор высокоуровневых API, с которыми работает Android-разработчик:

- Activity Manager управляет экранами приложения;
- Resource Manager предоставляет доступ к строкам, изображениям, цветам и layout-файлам;
- Notification Manager отвечает за уведомления;
- Content Providers помогают обмениваться данными;
- View System отвечает за интерфейс.

### Applications

Верхний уровень - пользовательские и системные приложения: телефон, камера, браузер, настройки, а также приложения, которые создают разработчики.

---

## 5. Android Studio

Android Studio - официальная IDE для Android-разработки.

Возможности Android Studio:

- создание проекта по шаблону;
- редактор Java-кода;
- редактор XML-разметки;
- визуальный предпросмотр экранов;
- сборка проекта через Gradle;
- запуск на эмуляторе или устройстве;
- отладчик;
- Logcat для просмотра системных и пользовательских логов;
- профилировщики производительности.

## 6. Структура Android-проекта · продолжение

```text
app/
  src/
    main/
      java/...
        MainActivity.java
      res/
        layout/
          activity_main.xml
        values/
          strings.xml
          colors.xml
          themes.xml
      AndroidManifest.xml
  build.gradle
build.gradle
settings.gradle
```

---

## 6. Структура Android-проекта · продолжение

Главные файлы:

- `MainActivity.java` - Java-класс основного экрана;
- `activity_main.xml` - XML-разметка экрана;
- `AndroidManifest.xml` - описание компонентов приложения и разрешений;
- `strings.xml` - текстовые ресурсы;
- `colors.xml` - цвета;
- `build.gradle` - настройки сборки и зависимости.

## 7. Первый проект Hello World

Алгоритм демонстрации:

1. Открыть Android Studio.
2. Создать новый проект.
3. Выбрать шаблон Empty Views Activity или Empty Activity с XML-разметкой.
4. Указать язык Java.
5. Выбрать минимальную версию SDK.
6. Дождаться синхронизации Gradle.
7. Открыть `activity_main.xml`.
8. Изменить текст на экране.
9. Запустить приложение на эмуляторе.

Пример `activity_main.xml`:

## 7. Первый проект Hello World · продолжение

Пример `MainActivity.java`:

## 7. Первый проект Hello World · продолжение

```java
package com.example.helloworld;

import android.os.Bundle;
import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
    }
}
```

---

## 7. Первый проект Hello World · продолжение

Важно объяснить студентам:

- `setContentView()` связывает Activity с XML-разметкой;
- `R.layout.activity_main` - автоматически сгенерированная ссылка на ресурс;
- `onCreate()` вызывается при создании Activity.

## Типичные ошибки

- проект создан на Kotlin, хотя нужен Java;
- не установлен SDK;
- эмулятор не запускается из-за отключенной виртуализации;
- студент изменяет файл в режиме Preview, но не XML;
- в XML пропущена закрывающая кавычка или тег.
