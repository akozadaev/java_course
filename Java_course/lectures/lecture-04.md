# Лекция 4. Условия циклы методы и область видимости

Версия для чтения. Основа: [рекомендации к лекции 4](lecture-04.md).

**Цель:** Разбивать решение на методы и управлять ходом выполнения.

## Основные понятия

Управляющие конструкции выбирают путь выполнения. `if` подходит для произвольных
логических условий; `switch` — для выбора по одному значению. `switch expression` возвращает результат; ветви со стрелкой не допускают случайного перехода в следующую ветку. Все варианты должны быть покрыты либо ветками, либо `default`.

Цикл `for` удобен, когда явно известны инициализация, условие и изменение
счётчика. Enhanced `for` читает элементы массива или `Iterable`, но не даёт
индекс. `while` выражает повторение до изменения условия. Бесконечный цикл — не
ошибка сам по себе, если выход управляется корректно, но в учебных алгоритмах
условие завершения должно быть очевидно.

Метод имеет имя, параметры, возвращаемый тип и тело. Маленькие методы позволяют
дать имена этапам алгоритма и тестировать их отдельно. Перегрузка означает одно
имя с разными списками параметров; возвращаемый тип сам по себе не различает
перегрузки.

Java всегда передаёт аргументы по значению. Для примитива копируется значение,
для объекта — значение ссылки. Метод может изменить доступный через ссылку
объект, но не может заменить переменную вызывающего кода другой ссылкой.

Локальная переменная существует только внутри своего блока. Чем уже область
видимости, тем меньше состояний приходится держать в голове. Ранний возврат для
ошибочного ввода сокращает вложенность, но множество хаотичных выходов из
сложного метода тоже ухудшает чтение.

## От модели к решению

### Ветвления и границы

В примере оценки допустимы от 0 до 100 включительно. Проверка диапазона выполняется до switch, затем деление на 10 объединяет оценки в десятки. `case 10, 9` даёт A для 90–100, а `case 6` — D для 60–69. Значения 59 и 60 особенно полезны для проверки: они проходят по разным веткам.

В форме switch с `->` нет неявного перехода в следующую ветку. Каждая допустимая ветка switch expression должна дать значение либо завершиться исключением. У классической формы с двоеточиями другие правила: там может понадобиться break.

### Цикл и состояние

Для суммы оценок нужен аккумулятор. До первой итерации он равен нулю, после каждой — сумме просмотренных элементов. Это инвариант цикла. Минимум нельзя бездумно инициализировать нулём, если все оценки положительные: после проверки непустого входа разумнее взять первый элемент.

Среднее требует дробного деления: сумма делится на `(double) count`. Для пустого набора среднего нет. Контракт должен выбрать исключение или явное представление отсутствующего результата. Возврат нуля смешивает отсутствие данных с реальным средним ноль.

`break` завершает цикл, `continue` переходит к следующей итерации, `return` завершает метод. При ручном изменении счётчика важно, чтобы continue не пропускал шаг, необходимый для завершения.

### Что получает метод

Параметр `int[] scores` получает копию ссылки. Запись `scores[0] = 100` меняет общий объект, а `scores = new int[0]` — только локальную переменную. Метод статистики может обещать не изменять вход и создавать копию для сортировки.

Перегрузка выбирается компилятором по сигнатурам и статическим типам аргументов. Она отличается от переопределения, где поведение зависит от фактического класса объекта.

## Практический пример

Ниже приведён учебный фрагмент. Структура проекта, зависимости и команды запуска находятся в [проекте лекции 4](../examples/lecture-04-control-flow/README.md).

```java
public class Grade {
    static String label(int score) {
        if (score < 0 || score > 100) throw new IllegalArgumentException();
        return switch (score / 10) {
            case 10, 9 -> "A";
            case 8 -> "B";
            case 7 -> "C";
            case 6 -> "D";
            default -> "F";
        };
    }
}
```

## Разбор и проверка результата

### Отдельный метод и общий алгоритм

Для набора `60, 90, 100` минимум равен 60, максимум — 100, сумма — 250, среднее — примерно 83,33. Категория среднего зависит от требования: если метод label принимает int, нельзя молча отбрасывать дробную часть без объяснения. Альтернатива — вычислять категорию каждого балла отдельно или определить правило перевода среднего в категорию.

Повторное использование label помогает держать пороги в одном месте. Если тот же набор условий скопировать в обработку списка и вывод отчёта, последующая смена границы может исправить один путь и оставить другой прежним.

Область видимости не равна гарантированному времени существования объекта в памяти. Локальная ссылка выходит из блока, но объект может остаться достижим через другие ссылки. Для алгоритма важно, какие имена доступны на данном участке и какие изменения наблюдает вызывающий код.

## Типичные ошибки

- условие цикла никогда не меняется;
- `<= array.length` вместо `< array.length`;
- дублирование одинаковых условий в нескольких методах;
- изменение коллекции внутри enhanced `for`;
- ожидание, что метод заменит переданный объект присваиванием параметру.
