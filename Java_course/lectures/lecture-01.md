# Лекция 1. Платформа Java и первый запуск

Версия для чтения. Основа: [рекомендации к лекции 1](lecture-01.md).

**Цель:** Различать JDK, JVM и стандарт Java SE; установить JDK; скомпилировать и запустить программу.

## Основные понятия

Java — одновременно язык программирования, стандартная библиотека и платформа
выполнения. Исходный файл `.java` читает компилятор `javac` и создаёт байткод в
файле `.class`. Команда `java` запускает JVM, загружает класс, проверяет байткод и
вызывает метод `public static void main(String[] args)`. Благодаря промежуточному
байткоду одна и та же программа может работать в разных ОС при наличии
совместимой JVM.

JDK содержит инструменты разработчика: компилятор, launcher, `jshell`, `javadoc`,
`jar`, диагностические утилиты и стандартную библиотеку. JVM — виртуальная машина, исполняющая байткод; это не полный комплект инструментов разработки. Java SE задаёт спецификации языка, виртуальной машины и API.
Поэтому фраза «Java установлена» неоднозначна: для разработки нужен именно JDK,
а команда `java --version` должна показывать выбранную версию.

Имена файлов и классов связаны: публичный класс `Main` хранится в `Main.java`.
Java чувствительна к регистру, поэтому `Main`, `main` и `MAIN` — разные имена.
Компилятор сообщает ошибки до запуска, а исключения возникают уже во время
выполнения. Это различие важно при диагностике.

Classpath — список мест, где JVM ищет классы. На первом занятии достаточно
текущего каталога: `javac Main.java`, затем `java Main`. Расширение `.class` в
команде запуска не пишется. Модуль `java.base` подключается автоматически и
содержит базовые классы `String`, `System`, коллекции и ввод-вывод.

`jshell` удобен для коротких экспериментов: выражение выполняется без создания
класса. Но учебные решения следует сохранять в исходниках, чтобы их можно было
повторить, проверить и передать другому человеку.

## От модели к решению

### Версии языка и совместимость

В курсе используется JDK 25. Возможности языка описывает Java Language Specification (JLS), формат class-файлов и выполнение — JVM Specification, а доступные классы и методы — Java SE API. Эти документы отвечают на разные вопросы: допустим ли синтаксис, как выполняется байткод и каков контракт библиотечного метода.

Новые feature-релизы Java выходят с полугодовым ритмом. LTS означает длительную поддержку выбранного выпуска конкретным поставщиком; сроки и условия зависят от дистрибутива. Для учебного проекта важна единая версия команды. Preview-возможности требуют специальных флагов и в обязательных примерах не используются.

Байткод переносим при наличии совместимой среды и необходимых библиотек. Старая JVM обычно не умеет читать class-файл нового формата. Параметр `javac --release` позволяет компилировать под поддерживаемый предыдущий выпуск, ограничивая также стандартное API. Нативные библиотеки могут дополнительно ограничить переносимость.

### От исходника до запуска

Классический цикл состоит из двух команд: `javac Main.java` создаёт `Main.class`, затем `java -cp . Main` запускает класс из текущего каталога. Если исходник изменился, нужна новая компиляция: иначе сохранится старое поведение. В команде запуска указывается имя класса, а не имя class-файла.

`java Main.java` использует другой режим: исходник компилируется автоматически для запуска. Отсутствие нового `Main.class` рядом с исходником в этом случае не является ошибкой. В JDK 25 существуют также компактные исходники и instance main methods; здесь используется классическая форма main, чтобы явно видеть структуру класса.

Аргументы после имени класса попадают в `args` как строки. Прежде чем обращаться к `args[0]`, программа проверяет их количество. Преобразование строки в число — отдельная операция: `abc` не является целым числом и вызывает диагностируемую ошибку.

## Практический пример

Ниже приведён учебный фрагмент. Структура проекта, зависимости и команды запуска находятся в [проекте лекции 1](../examples/lecture-01-platform-first-run/README.md).

```java
// Main.java
public class Main {
    public static void main(String[] args) {
        System.out.println("Java " + Runtime.version());
    }
}

// Запуск:
// javac Main.java
// java Main
```

## Разбор и проверка результата

### Проверка первого запуска

После `java Main` появляется строка `Java 25...`: точная версия обновления зависит от установленного JDK. Если возникает `ClassNotFoundException`, JVM не нашла названный класс в доступных местах. Это другая ситуация, чем сообщение оболочки «java: command not found», когда не найден сам исполняемый инструмент.

Для класса с пакетом команда запуска содержит полное имя, например `java -cp out course.demo.Main`. Корень classpath — каталог out, внутри которого находятся каталоги course/demo. Добавлять в classpath непосредственно каталог с Main.class при этом неправильно: имя пакета является частью имени класса.

Полезно различать три наблюдения: javac завершился успешно, class-файл действительно обновился, java запустила именно этот класс. Открытие исходника в IDE не доказывает ни одного из них. Поэтому первые шаги выполняются из терминала с явно выбранным рабочим каталогом.

## Типичные ошибки

- смешивают режим `java Main.java` (single-file launch) и цикл `javac` + `java`, из-за чего путаются в `.class` и classpath;
- пишут `java Main.class`;
- запускают команду не из каталога с классом;
- используют JRE вместо JDK и не находят `javac`;
- не заключают путь с пробелами в кавычки.

## Самостоятельная работа

Установить JDK 25, вывести версию среды, аргументы командной строки и сумму двух целых чисел.

**Рекомендации к решению.** Сначала выполнить команды вручную. В отчете привести вывод java --version, дерево файлов и два запуска с разными аргументами.

**Критерии приёмки.** Проект компилируется без IDE; неверное число аргументов обрабатывается понятным сообщением; исходник сохранен в UTF-8.
