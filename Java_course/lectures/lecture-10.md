# Лекция 10. Функциональные интерфейсы лямбда выражения и Stream API

Версия для чтения. Основа: [рекомендации к лекции 10](lecture-10.md).

**Цель:** Строить понятные конвейеры обработки без побочных эффектов.

## Основные понятия

Функциональный интерфейс имеет один абстрактный метод. `Predicate<T>` проверяет
условие, `Function<T,R>` преобразует, `Consumer<T>` выполняет действие,
`Supplier<T>` создаёт значение. Лямбда — компактная реализация такого контракта,
а не отдельный тип функции. Ссылка на метод применяется, когда она яснее
эквивалентной лямбды.

Stream описывает ленивый конвейер, а не хранит данные. Источник порождает поток,
промежуточные операции `filter`, `map`, `flatMap` формируют преобразование,
терминальная операция запускает обработку. Один stream нельзя использовать
повторно. Порядок операций влияет на объём работы и иногда на результат.

`map` преобразует один элемент в один, `flatMap` раскрывает вложенную структуру,
`filter` оставляет элементы, `reduce` сворачивает их в значение. Collectors
создают списки, карты и группировки. При `toMap` нужно определить поведение для
повторяющихся ключей.

Конвейер проще понимать, когда функции не меняют внешнее состояние. Побочный
эффект в `map` становится особенно опасным при `parallelStream`. Обычный цикл
лучше, если алгоритм содержит сложное ветвление, несколько изменяемых
аккумуляторов или ранний выход, который stream выражает неясно.

`Optional` моделирует возможное отсутствие результата метода. Он не заменяет все
`null`, не предназначен для полей entity и коллекций Optional. Для пустой
коллекции возвращают пустую коллекцию. `orElse` вычисляет аргумент заранее, а
`orElseGet` — лениво.

## От модели к решению

### Функция и конвейер

Лямбда получает тип из целевого функционального интерфейса. `sale -> sale.amount() > 0` может стать Predicate, а `Sale::category` — Function. Захваченная локальная переменная должна быть final или effectively final; объект по этой ссылке всё ещё может оставаться изменяемым.

Промежуточные операции обычно ленивы. Без терминальной операции конвейер не обходит источник. Реализация может не вызывать некоторые функции, если результат удаётся получить иначе. Поэтому обязательное действие нельзя помещать в peek в надежде, что оно всегда выполнится.

### От продаж к отчёту

`groupingBy` строит карту категорий, а summingLong складывает суммы каждой группы. Значения выражены в минимальных денежных единицах. В примере нет признака отмены: фильтрация отменённых продаж в задании потребует расширения входной модели.

Порядок ключей карты не задан. Для отчёта по убыванию суммы можно сортировать entrySet по значению и добавить вторичный порядок по имени категории. Это делает результат воспроизводимым при равных суммах. `summingLong` не диагностирует переполнение: для больших диапазонов нужен другой числовой контракт.

Если каждый заказ содержит позиции, flatMap превращает поток заказов в один поток позиций. Map вместо этого дал бы поток списков — другую структуру.

### Отсутствие и параллельность

Optional.empty означает отсутствие одного результата. Get без проверки может бросить NoSuchElementException. Map, orElseGet и orElseThrow выражают последующий сценарий. Optional делает отсутствие видимым в типе, но не заставляет обработать его правильно.

ParallelStream не гарантирует ускорения. Запись во внешний ArrayList нарушает безопасность при конкуренции. Даже правильный collector требует затрат на разбиение и объединение; решение о параллельности принимается после измерения подходящего сценария.

## Практический пример

Пример сохраняется в `SalesReport.java` и запускается командами `javac SalesReport.java` и `java SalesReport`. Структура проекта, зависимости и команды запуска находятся в [проекте лекции 10](../examples/lecture-10-streams-report/README.md).

```java
import java.util.*;

public class SalesReport {
    record Sale(String category, long amount) {}

    static Map<String, Long> totals(List<Sale> sales) {
        return sales.stream().collect(java.util.stream.Collectors.groupingBy(
            Sale::category,
            java.util.stream.Collectors.summingLong(Sale::amount)
        ));
    }

    public static void main(String[] args) throws Exception {
        System.out.println(totals(List.of(new Sale("books", 2000), new Sale("books", 1500), new Sale("games", 5000))));
    }
}
```

`Collectors.groupingBy` не принимает `null` в качестве ключа: если `Sale.category`
может быть `null`, заранее отфильтруйте или замените категорию значением по
умолчанию, иначе получите `NullPointerException`.

## Разбор и проверка результата

### Итог отчёта и операция reduce

В примере две продажи books по 2000 и 1500 дают итог 3500, одна games на 5000 — итог 5000. Это суммы в минимальных денежных единицах, а не форматированный текст с валютой. Представление денег относится к последнему этапу отчёта.

Тот же общий итог можно получить через mapToLong и sum. Reduce применяется к более общему сворачиванию; для корректного параллельного объединения важны ассоциативность и нейтральный элемент. Вычитание не является заменой сложения в таком сворачивании: результат зависит от группировки.

OrElse получает уже вычисленный аргумент. Поэтому `optional.orElse(loadDefault())` вызывает loadDefault даже при наличии значения. Вариант `orElseGet(() -> loadDefault())` выполняет вычисление только при отсутствии. Это влияет и на стоимость, и на побочные эффекты, особенно если загрузка обращается к сети.

## Типичные ошибки

- повторное использование stream;
- изменение внешнего списка внутри `map`;
- `parallelStream` для маленькой коллекции или блокирующего I/O;
- `Optional.get()` без проверки;
- огромный конвейер без именованных методов.

## Самостоятельная работа

Сформировать отчет по продажам: отфильтровать отмененные операции, сгруппировать по категории и отсортировать итог.

**Рекомендации к решению.** Разделить преобразование данных и вывод. Не изменять внешние коллекции внутри map или filter.

**Критерии приёмки.** Конвейер не содержит побочных эффектов; null не используется вместо пустой коллекции; сложный участок вынесен в именованный метод.
