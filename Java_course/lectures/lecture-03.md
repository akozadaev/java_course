# Лекция 3. Переменные примитивные типы и операторы

Версия для чтения. Основа: [рекомендации к лекции 3](lecture-03.md).

**Цель:** Выбирать тип данных и объяснять преобразования и переполнение.

## Основные понятия

Переменная связывает имя, статический тип и текущее значение. Восемь примитивных
типов хранят непосредственно число, символ или логическое значение. Целые типы
различаются диапазоном, `float` и `double` реализуют двоичную плавающую точку,
`char` хранит одну кодовую единицу UTF-16, а `boolean` принимает только `true`
или `false`.

Тип определяет допустимые операции ещё при компиляции. Неявное расширение
(`int` → `long`) обычно безопасно; сужение требует cast и может потерять данные.
Арифметика `byte` и `short` вычисляется как `int`. Деление двух `int` отбрасывает
дробную часть до присваивания: `5 / 2` равно `2`, даже если результат записан в
`double`.

Целые типы переполняются циклически без исключения. Для данных, где переполнение
является ошибкой, применяют `Math.addExact`, `multiplyExact` или `BigInteger`.
`double` подходит для измерений с допустимой погрешностью, но не для денег:
десятичная дробь `0.1` не представима точно в двоичной системе.

`BigDecimal` хранит десятичное значение и масштаб. Его создают из строки:
`new BigDecimal("19.90")`. При делении следует явно указать масштаб и
`RoundingMode`, иначе для бесконечной десятичной дроби возникнет
`ArithmeticException`. Сравнение численного значения выполняют через
`compareTo`, потому что `equals` учитывает также масштаб.

`var` выводит статический тип локальной переменной из инициализатора. Это не
динамическая типизация: тип остаётся фиксированным. `var` полезен, когда правая
часть ясна, но ухудшает чтение для литералов и неинформативных фабричных методов.

## От модели к решению

### Как вычисляется выражение

Тип выражения определяется операндами, а не переменной слева. В `double average = 5 / 2` сначала выполняется целочисленное деление, затем `2` расширяется до `2.0`. Для дробного результата один операнд должен стать вещественным до деления: `5 / 2.0`.

Расширение не всегда сохраняет точность: `int` полностью помещается в `long`, но не каждое значение `long` точно представимо в `double`. Приведение к более широкому типу после переполнения не восстанавливает потерянные данные. При умножении двух `int` можно сначала расширить один операнд до `long` или применить `Math.multiplyExact` с подходящими типами.

Литерал `3_000_000_000L` имеет тип long; суффикс нужен уже при разборе исходника. Операторы `&&` и `||` вычисляют правую часть только при необходимости. Поэтому `value != null && value.isEmpty()` не обращается к методу через null.

### Десятичные вычисления

В примере `19.90 × 3` даёт `59.70`. Для налога 7,5% сумму можно умножить на `new BigDecimal("1.075")`, затем вызвать `setScale(2, RoundingMode.HALF_UP)`. Момент округления является частью требования: округление каждой позиции и округление общей суммы могут дать разные итоги.

`new BigDecimal(0.1)` сохраняет десятичное представление уже приближённого двоичного double. Конструктор из строки сохраняет заданное десятичное число. Методы BigDecimal возвращают новый объект: `total.setScale(...)` без использования результата не изменяет total.

Оператор `==` для объектов сравнивает ссылки. `equals` у BigDecimal различает `2.0` и `2.00`, а `compareTo` считает их численно равными. Выбор зависит от контракта. Для денег дополнительно требуется валюта: точная арифметика сама по себе не разрешает складывать рубли и евро.

## Практический пример

Ниже приведён учебный фрагмент. Структура проекта, зависимости и команды запуска находятся в [проекте лекции 3](../examples/lecture-03-types-and-money/README.md).

```java
import java.math.BigDecimal;

public class MoneyDemo {
    public static void main(String[] args) {
        var price = new BigDecimal("19.90");
        var quantity = 3;
        var total = price.multiply(BigDecimal.valueOf(quantity));
        System.out.println(total); // 59.70
    }
}
```

## Разбор и проверка результата

### Контрпример и проверяемая граница

Выражение `Integer.MAX_VALUE + 1` даёт отрицательное значение: обычная целочисленная арифметика не сообщает о переполнении. `Math.addExact(Integer.MAX_VALUE, 1)` вместо этого бросает ArithmeticException. Здесь важна реакция вызывающего кода: недостаточно заменить метод, если затем исключение молча превращается в ноль.

Для сравнения измерений в double часто задают допустимую абсолютную или относительную погрешность. Универсальной константы epsilon для всех диапазонов нет. Сравнение через `==` само по себе разрешено, но может не выражать ожидаемую близость вычисленных величин. NaN и бесконечности также требуют сознательной политики.

BigDecimal устраняет ошибку двоичного представления десятичных входов, но не выбирает за разработчика налоговое правило, валюту или округление. В отчёте по денежной задаче должны быть видны и исходные значения, и правило получения окончательного масштаба.

## Типичные ошибки

- деньги в `double`;
- создание `BigDecimal` из `double`;
- cast после уже выполненного целочисленного деления;
- сравнение чисел с плавающей точкой оператором `==`;
- `var` без понятного контекста.
