# Тема: Vaadin Flow: основы UI

**Цель темы.** Серверный UI на Java и жизненный цикл компонентов.

**Общая постановка.** Маршрут открывается. Binder показывает ошибки до сохранения. Клавиатурная навигация базово работает. Grid обновляется после успеха.

## Варианты

### Вариант 1. Список + форма товара

**Задание.** Сценарий «Список + форма товара». Страница: Grid товаров и форма создания с Binder и Bean Validation. При ошибках поля подсвечиваются до сохранения; после успеха Grid обновляется. Оформите решение отдельным Maven-модулем или проектом по общим правилам `assignments/README.md`; в README варианта укажите команды запуска/тестов и какие граничные случаи проверены.

**Критерии приёмки.** Маршрут открывается; клавиатурой можно пройти форму; без сохранения невалидных данных.

### Вариант 2. Диалог подтверждения удаления

**Задание.** Сценарий «Диалог подтверждения удаления». Удаление элемента из Grid только после ConfirmDialog. Отмена закрывает диалог без вызова сервиса удаления. Оформите решение отдельным Maven-модулем или проектом по общим правилам `assignments/README.md`; в README варианта укажите команды запуска/тестов и какие граничные случаи проверены.

**Критерии приёмки.** Подтверждение вызывает сервис один раз; тест сценария или явная проверка listener.

### Вариант 3. Фильтр Grid

**Задание.** Сценарий «Фильтр Grid». TextField над Grid фильтрует in-memory список по подстроке имени (без учёта регистра). Пустой фильтр показывает все элементы. Оформите решение отдельным Maven-модулем или проектом по общим правилам `assignments/README.md`; в README варианта укажите команды запуска/тестов и какие граничные случаи проверены.

**Критерии приёмки.** Фильтрация не пересоздаёт бессмысленно весь UI; данные-источник не портятся.

### Вариант 4. Форма пароля

**Задание.** Сценарий «Форма пароля». Два PasswordField: пароль и подтверждение. Binder validator проверяет совпадение и минимальную длину. Не логируйте plaintext. Оформите решение отдельным Maven-модулем или проектом по общим правилам `assignments/README.md`; в README варианта укажите команды запуска/тестов и какие граничные случаи проверены.

**Критерии приёмки.** Ошибка видна до submit; успешный submit вызывает сервис с хешированием на стороне сервера (заглушка ок).

### Вариант 5. Навигация с параметром

**Задание.** Сценарий «Навигация с параметром». Из списка переходите на маршрут /items/{id}. Детальная view читает id из маршрута. Несуществующий id показывает понятное сообщение, а не stack trace. Оформите решение отдельным Maven-модулем или проектом по общим правилам `assignments/README.md`; в README варианта укажите команды запуска/тестов и какие граничные случаи проверены.

**Критерии приёмки.** Back возвращает к списку; глубокая ссылка работает после refresh (если session позволяет — описать).

### Вариант 6. Upload файла (учебно)

**Задание.** Сценарий «Upload файла (учебно)». Upload принимает только .txt до N КБ, показывает имя и размер. При превышении лимита — Notification с ошибкой, файл не сохраняется. **Задание.** Сценарий «Кастомный converter Binder». Поле цены в форме связано с BigDecimal через Converter Binder. Неверный ввод показывает ошибку поля, а не падает с необработанным исключением.
