# Тема: Параллельность и виртуальные потоки

**Цель темы.** Безопасно выполнять независимые блокирующие операции и корректно завершать задачи.

**Общая постановка.** Гонку демонстрируйте синхронизаторами, не `sleep`. Executor закрывайте. ScopedValue — обзорно, не обязателен в решении.

## Варианты

### Вариант 1. Счётчик: гонка + 3 фикса

**Задание.** Сценарий «Счётчик: гонка + 3 фикса». synchronized, Lock, AtomicInteger; воспроизводимый тест. Оформите решение отдельным Maven-модулем или проектом по общим правилам `assignments/README.md`; в README варианта укажите команды запуска/тестов и какие граничные случаи проверены.

**Критерии приёмки.** Без sleep как способа создать гонку; точный итог.

### Вариант 2. Future исключение

**Задание.** Сценарий «Future исключение». Задача в ExecutorService бросает известное RuntimeException. Через Future.get() извлеките ExecutionException и проверьте cause. Покажите, что isDone() недостаточен. Оформите решение отдельным Maven-модулем или проектом по общим правилам `assignments/README.md`; в README варианта укажите команды запуска/тестов и какие граничные случаи проверены.

**Критерии приёмки.** Тест проверяет тип cause; исполнитель закрывается.

Измерьте пик конкуренции внутри критической секции. Оформите решение отдельным Maven-модулем или проектом по общим правилам `assignments/README.md`; в README варианта укажите команды запуска/тестов и какие граничные случаи проверены.

**Критерии приёмки.** Пик ≤ 10; try-with-resources на executor; в README — что close() ждёт завершения задач.
