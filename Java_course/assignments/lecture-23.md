# Тема: Vaadin и Spring: прикладная архитектура

**Цель темы.** Связать UI, сервис и Spring Data без дублирования логики.

**Общая постановка.** Права на сервере. Прямой URL не обходит авторизацию. UI без SQL. findAll в конструкторе View — только для крошечных данных; иначе DataProvider/пагинация.

## Варианты

### Вариант 1. Экран заказов + роли

**Задание.** Сценарий «Экран заказов + роли». Список заказов, переход к карточке, доступ только роли OPERATOR (или аналог). UI вызывает сервис, не repository. Тест критического сценария. Оформите решение отдельным Maven-модулем или проектом по общим правилам `assignments/README.md`; в README варианта укажите команды запуска/тестов и какие граничные случаи проверены.

**Критерии приёмки.** Прямой URL без роли недоступен; в View нет SQL/JPA.

**Задание.** Сценарий «DataProvider пагинация». Grid заполняется через DataProvider.fromCallbacks (или аналог) с page/size из сервиса. В конструкторе View запрещён findAll() всего каталога.
